# ADR-005 — 近期主线转向：轻量图形化 IDE + Agent 会话管理

日期：2026-10-02（会话内定向）
状态：**已定向**（项目所有者确认）
关联：
- 修订 `VISION-AND-ROADMAP.md` §3.3 / §8 的"近期目标"（M1.9 不再是近期唯一主线）
- 修订 ADR-004 的**落地顺序**（"fork 先行"→"stock VSCode + 扩展先行，必要时再 fork"）；ADR-004 的载体选择（VSCode 系）与 ADR-002 交互模型不变
- 不改 `M1-DESIGN.md` 的契约面、DONE 不变量、里程碑链

---

## 背景：项目所有者的真实痛点

1. **IDE 太重**：IDEA 常驻占用 10G 以上内存，整机只有 16G；日常主力工作已转向 AI Agent 开发，IDE 只用于查询/审核代码、搜索定位、提交与看提交记录、编译与 debug。
2. **Agent 会话难管**：claude / codex 会话开太多占内存；iTerm2 窗口易被误关，会话找回、切换不方便；Agent 与 IDE 之间切换工作状态有摩擦。
3. 期望：轻量的**图形化**、IDEA 式交互的 IDE，带比 iTerm2/tmux 更好用的会话管理，参考 Cursor 的视图切换，视图之间联动（工作区改动、提交、编译、debug）。Neovim 路线已试过，原型交互始终不满意（vim 类做不出 IDEA 式图形交互），故改走 VSCode 系（ADR-004）。

## 偏离的复盘

M1.0–M1.8.5 全部是**无界面**的工作流/契约/验收链；用户最在意的图形交互直到 2026-09-19 才开始，且一天内堆到 13 个提交，真实需求被压到最后。M1.9（真实 codex + Maven 端到端 + G1–G6）验收的是工程工作流那条链，**不缓解上述任何一个痛点**。另外，UI-1 的 VSCode fork 工作副本放在 `/tmp/vscode-ui1`，2026-10-02 检查时已被系统清理（目录空、无 `.git`）；仓库内仅留 S1 补丁与规格附录 H 的文字描述。

## 决定

1. **近期主线 = 轻量图形化 IDE + Agent 会话管理**。每个近期里程碑必须带至少一条**用户可感知的验收**，并能对应到上面某个痛点（例如"关闭窗口会话仍在""会话找回/切换的操作步数""IDE 常驻内存相对 IDEA"）。
2. **第一块交付 = `agentdeck`**（`agentdeck/`，独立工具）：索引 `~/.claude`、`~/.codex` 历史会话；agent 跑在独立 tmux server，关窗口/杀服务不中断；休眠（结束进程）与恢复（`--resume`）；状态/标签/置顶/别名与筛选；Web 窗口接入终端。通过 `ide_cmd` 配置调起轻量 IDE，二者松耦合。
3. **IDE 载体顺序**：先用 stock VSCode + 自写扩展做会话树、视图切换、改动文件联动 diff；只有扩展 API 做不到的壳层需求（标题栏、整体布局）才 fork。即提前启用 ADR-004 证伪条件②的退路。UI-1 fork 线暂停，不恢复丢失的副本，除非后续确有壳层需求。
4. **保留 Go 内核 + 插件架构**，初衷是把大工程拆成"内核 + 很多插件"，使每个插件都能在 Agent 单次会话的上下文内开发完，不受会话长度与记忆限制。会话托管能力待 agentdeck 原型稳定后，**契约先行**下沉为插件（`contracts/` 新增能力、`check-arch.sh` 护栏照常），agentdeck 改为其客户端。
5. **M1.9 暂缓，不删除**：计划与规格保留；待会话管理与 IDE 联动落地、有真实使用方后再恢复，届时它还可作为读投影的真实消费方验收。

## 影响

- `kernel/`、`plugins/`、`contracts/`：无改动。
- README / VISION 的"近期目标"同步改写（本次提交）。
- `scripts/qualify-m1.sh` 继续不实现，直至 M1.9 恢复。

## 未决

- 轻量 IDE 选型与安装：本机目前只有 IDEA，未安装 VSCode；`ide_cmd` 暂未配置。
- 内存收益未量化：需对比"IDEA 常驻"与"VSCode + Java 扩展 + agentdeck"的实测占用，作为后续验收基线。
- agentdeck 窗口目前为 Chrome app 模式（额外一份 Chrome 进程内存，未测量）；是否换成 VSCode 扩展内置视图，待使用一段时间后再定。

## 证伪（退出条件）

1. agentdeck 日常使用一段时间后，"误关丢会话 / 找回困难 / 切换慢"仍未明显改善 → 回到会话模型（tmux 托管 vs 自研 PTY 托管）重新设计。
2. stock VSCode + 扩展无法承载所需的视图联动 → 才启动 fork（并将 fork 源码放入持久目录并推远端，禁止放 `/tmp`）。
3. 轻量 IDE 的实测内存没有显著低于 IDEA → 重新评估载体。
