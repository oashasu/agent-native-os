## The M3 problem — root cause + verified fix

**Test** (`plugins/agent-harness/real_provider_test.go`, `TestRealProviderKillsProcessGroup`, from Codex's plan edit):

```go
p := RealProvider{name: "shell", bin: "/bin/sh", env: []string{}, timeout: 500 * time.Millisecond,
    argv: func(RunSpec) []string { return []string{"-c", `/bin/sleep 5 & echo $! > "$1"; wait`, "sh", pidFile} }}
res := runRealWithPID(t, pidFile, p, ...)   // expects StatusTimeout
assertPidGone(t, pidFile)                    // polls syscall.Kill(sleepPid, 0) up to 100×50ms = 5 s
```

**Why the no-op mutation doesn't bite:** with `killProcessGroup` a no-op, on the 500 ms deadline `Run` waits its 3 s grace, then the fallback `cmd.Process.Kill()` SIGKILLs `/bin/sh` (direct child) at ~t=3.5 s. `/bin/sleep 5` (started at t=0) is reparented to init and **exits on its own at t=5 s** — inside `assertPidGone`'s 5 s poll window → the test sees `ESRCH` and PASSES (just slower: 0.5 s → ~5 s).

**Verified fix** (I reproduced both the failure and the fix locally on `origin/chatgpt/m1-8-real-provider-adapter`):
change the descendant to outlive any test window — `/bin/sleep 5` → **`/bin/sleep 60`** in that test's argv. Then:
- clean implementation → PASS in **0.50 s** (process group killed at t=500 ms, sleep gone immediately)
- no-op `killProcessGroup` → **FAIL** `pid <N> still alive` in ~8.6 s (sh killed by fallback, `sleep 60` survives past the poll window)
- `t.Cleanup` → `killRecordedPID(pidFile)` reaps the leaked `sleep 60`; no process leak.

This is a **test fix, not a production fix.** Do NOT change `killProcessGroup` / `Run` to satisfy the test.
