# M0.5 Patch 12 — Provider Error Passthrough

Patch line: **v0.9.4**  
Status: **Focused issue closed; overall M0.5 remains open**

## Problem

Before this patch, the Router treated a provider-produced `KindError` as if the route itself had failed:

```text
Provider: NOT_FOUND / CONFLICT / BUSINESS_ERROR
        ↓
Router converts to Go error
        ↓
Gateway / upstream wraps it
        ↓
INVOKE_ERROR / ROUTE_ERROR
```

That destroys information required by Workflow retry/reconciliation policy. A version conflict is not the same failure class as provider disconnection or route unavailability.

## Rule

The transport boundary now distinguishes:

```text
Provider Protocol Error
!=
Kernel / Transport Error
```

A provider `KindError` is a valid routed response. The Kernel must preserve its protocol semantics.

Kernel/transport errors remain things such as:

- provider runtime unavailable/disconnected;
- deadline while waiting for provider;
- capability resolution failure;
- authorization/admission failure;
- malformed protocol envelope.

Provider errors remain things such as:

- `NOT_FOUND`;
- `CONFLICT`;
- `BUSINESS_ERROR`;
- provider-defined retryable domain failures.

## Implementation

### Router

`internal/router/router.go` no longer turns a provider `KindError` into a Go route error. The original response envelope is returned unchanged.

### External Client Gateway

Because the Router no longer reports provider errors as invocation failures, the Gateway sends the provider error envelope directly to the client instead of generating `INVOKE_ERROR`.

### Public Go SDK

`sdk/go/protocol` adds a typed `RemoteError` for callers that prefer idiomatic Go `error` handling. It preserves:

```text
code
message
retryable
details
```

The response envelope is still returned as well.

## Tests

### Router unit test

A synthetic provider returns:

```text
CONFLICT
retryable=true
expected_version=7
```

The Router must return `KindError` with those fields intact and a nil route error.

### M0.5 external integration

The real `work-registry` is queried for a missing object. The external CLI must surface:

```text
NOT_FOUND: work not found
```

and must not contain:

```text
INVOKE_ERROR
ROUTE_ERROR
```

## Scope deliberately not included

This patch does not solve:

- principal/delegation propagation;
- Query/Command operation-kind enforcement;
- ordinary request cancellation routing;
- stream provider-crash/backpressure lifecycle;
- event publish/subscribe grants or host-derived actor integrity;
- stateful active-writer lease/fencing;
- contract-code generation or full compatibility analysis.

Those remain separate adversarial items so each change stays reviewable.
