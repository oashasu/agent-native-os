# M0.5 Adversarial Qualification — v0.10.0

Status: **PASSED by the repository's current qualification suite; Microkernel boundary remains a candidate, not a production security certification.**

This document supersedes the earlier claim that the v1 Kernel boundary was already closed. Historical documents `00` and `07` remain useful design records but their old closure status is not current.

## 1. Qualification objective

The target is not feature completeness. M0.5 asks whether the L0 host can safely support independently developed stateful and streaming capability plugins without freezing obvious identity, authorization, contract, failure, or authority flaws into dozens of future Engineering Work OS contracts.

## 3. Principal and delegation semantics

Four identities are intentionally distinct:

```text
Principal        authenticated human/service authority at the root
ImmediateCaller  plugin/runtime making this hop
ActorChain       Host-constructed call chain
DelegationID     opaque Host-held request authority context
```

A plugin cannot mint a stronger Principal by filling Envelope fields. For nested calls, Host policy requires the plugin's own declared/granted capability **and** either:

1. the Principal directly owns the child capability, or
2. the current Host-issued delegation scope explicitly permits the child capability.

A plugin that wants autonomous background/service authority must receive `service_authority` explicitly from Host policy; omission of delegation is not an escalation path.

## 4. Stateful authority semantics

Business state is owned by a **Logical Authority**, not by one process/plugin ID:

```text
Capability
  -> Logical Service
      -> Authority
          -> Storage Identity
              -> Active Writer Lease(epoch N)
                  -> Runtime Provider
```

Read-capable replicas may exist, but a mutating stateful Command must route to the active writer. Promotion advances the epoch. Storage mutation validates the runtime ID and epoch under a cross-process lock so a stale but still-running provider cannot commit after promotion.

This is a single-host reference fencing model, not distributed consensus. A multi-host implementation would require a storage/lease system with equivalent fencing guarantees.

## 5. Contract plane semantics

A Contract is more than the string `capability@major`:

```text
Contract identity
+ operation kind
+ JSON Schema request/response/event payload
+ semantic version
+ generated language binding
+ compatibility policy
```

Kernel admission verifies contract identity and operation kind. Generated Go bindings make Schema the current language source of truth. Unsupported JSON-Schema codegen constructs fail closed rather than silently generating an inaccurate SDK.

## 6. Stream/control separation

Bulk stream data may backpressure, but control messages such as Result/Error/Cancel/StreamClose and causally emitted Event admission must not silently disappear behind an unbounded data stream. The reference implementation therefore treats control and stream delivery separately and gives provider disconnect/client disconnect explicit termination semantics.

## 7. Host lifecycle/health states

The Supervisor exposes explicit host state vocabulary:

```text
INSTALLED
STARTING
READY
DEGRADED
BLOCKED
FAILED
STOPPED
```

`READY` depends on runtime health and required capability health; a process merely being alive is insufficient.

## 8. Current automated qualification

Run:

```bash
bash scripts/test.sh
```

It performs unit tests, race detector, generated-contract freshness, compatibility tests, schema/catalog validation, architecture fitness and process-level M0.5 attacks.

The integration suite deliberately includes:

- caller credential spoofing;
- read-only direct-write denial;
- confused-deputy attack through Composition;
- explicit delegated authority positive case;
- Query -> Command attack;
- provider business error passthrough;
- ordinary Command timeout/cancel with delayed side effect;
- stale live writer after fencing promotion;
- forced persistence failure;
- live external streaming and cancellation;
- external consumer disconnect;
- provider SIGKILL during stream;
- dynamic required dependency outage/recovery;
- malicious raw Event provenance forgery;
- unauthorized sensitive Event subscription;
- journal tampering;
- plugin crash/restart;
- Kernel restart;
- abrupt Kernel SIGKILL while a side effect is in flight.

## 9. What this qualification does not claim

M0.5 passing does not mean production hardening is complete. Current reference limitations include:

- no production-grade OS filesystem/network sandbox backend or secret broker isolation;
- no package signature/publisher trust chain;
- no distributed/multi-host consensus or lease service;
- only Go generated SDK is shipped;
- JSON Schema codegen deliberately supports a bounded subset and fails closed on unsupported shapes;
- no massive load/performance certification yet;
- local Unix transport is reference transport, not a hardened remote protocol deployment.

These should remain explicit rather than being disguised as completed security properties.

## 10. Gate decision

The external review's concrete M0.5 protocol/TCB blockers now have executable counter-tests in this repository. The correct status is therefore:

> **M0.5 current adversarial suite passes; L0 is eligible for another independent adversarial review.**

It is still premature to call this a production-grade kernel or permanently close all future kernel design discussion. The next decision should be made after an independent agent attacks this exact v0.10.0 package.
